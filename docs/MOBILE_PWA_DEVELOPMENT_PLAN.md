# MIGRA 移动工作台开发计划

更新日期：2026-09-23。当前状态：M0～M5 已完成源码实现和本地隔离验证；M6 的生产构建、自动化回归、部署权限、备份与成套恢复演练已在本机完成，并已部署到目标 NAS 验证公网 HTTPS、迁移、数据保持、基础性能和资源占用。iPhone／Android 真机安装、摄像头和文件选择器仍待验收。

## 产品边界

电脑端是完整办公工具；手机端用于查看、查询、待办、跟进和少量应急处理。手机端不复制桌面后台，也不另建一套业务服务。四个一级入口固定为**工作台、订单、搜索、我的**。

手机优先回答：现在有什么要处理、订单办到哪一步、有什么逾期或缺材料、人不在电脑旁能否完成一项简单操作。项目模板、流程与收付款计划设计、完整建单、复杂申请人编辑、批量材料、用户与角色、审计分析、系统配置、财务报表及备份恢复继续使用电脑端。

首版不做离线业务编辑、推送、原生安装包、Redis、独立搜索服务或移动专用业务后端。手机“快速建档”暂缓：现有订单创建会复制项目模板，不能为了手机入口生成缺流程、计划和材料的半成品订单；若以后确有需求，应先明确是独立线索还是沿用模板完整创建的草稿。系统已不使用独立合同金额，金额以应收／应付计划为准。

## 页面与业务口径

| 入口 | 手机首版重点 | 桌面保留 |
| --- | --- | --- |
| 工作台 `/m` | 逾期、今天、未来 7 天的真实数量及最早待办；按日期查看并直达来源模块 | 大量经营统计与报表 |
| 订单 `/m/orders` | 主申请人、项目、状态、当前阶段、下一日期；搜索、简单状态筛选、服务端排序和每页 10 条 | 复杂筛选、完整字段和批量操作 |
| 搜索 `/m/search` | 共用现有索引、权限和 `target_tab`，按订单／项目／代理分组 | 同一套服务端搜索规则 |
| 我的 `/m/me` | 当前身份、手机安全设置、安装说明、退出及唯一桌面入口 | 用户、角色、系统管理 |
| 订单详情 `/m/orders/[orderNo]` | 默认进入办理与跟进；收支、申请人与材料、合同与付款组成另外三个模块 | 全量编辑与复杂配置 |

工作台的三组数量必须在服务端按同一订单范围与权限完整统计，不能用最多 30 条的提醒列表推算。逾期是今天之前，今天是当前数据库业务日，未来 7 天是明日至第 7 日，三个区间互不重叠。列表每次只取对应区间最早 30 项；如果超过上限，应明确告知列表不是全部。已按计划原币结清的收付不再提醒，作废或恢复流水后按相同规则重新判断。

普通订单列表默认进入“办理与跟进”；提醒和搜索命中仍按现有 `target_tab` 直达流程、收支或材料。详情页只保留办理与跟进、订单收支、申请人与材料、合同与付款四个模块；顶部使用紧凑订单抬头保留申请人、项目、状态和负责人，四个模块采用单行吸顶页签。模块内容使用时间线和分组列表，办理与收支的主要操作固定在底部主导航上方；申请人较多时通过横向选择器切换，不同时展开所有材料卡片。只有相应权限才显示材料或财务模块。

流程手机端可阅读、完成当前步骤和新增跟进，沿用现有流程状态推进、版本冲突、权限范围及审计规则，不新增“添加结果”概念。跟进的业务日期与记录创建时间不同，界面展示具体时间时应取真实 `created_at` 并处理时区。收款与付款必须是独立表单、独立动作；整数最小货币单位、原币计划分配、汇率快照及金额联动沿用现有计算与校验。材料按申请人分组，公共合同／付款材料分开；可拍照、选相册／文件、上传和预览。护照 MRZ 识别仅辅助填表，必须人工核对确认；识别失败不删除已上传文件，也不阻断在电脑端人工填写。

目前手机端未专门设计项目／代理详情页，搜索命中只显示已有摘要，不从搜索页切换到桌面界面。用户只有在“我的”中主动选择“切换到桌面版”才会离开手机端。搜索不承诺找到尚未提取的 PDF 正文或图片文字。索引同步提示与有限自动刷新沿用现有实现。

## 实现和验收约束

- 继续使用 Next.js、PostgreSQL、现有 API、会话、搜索、附件及 MRZ 容器。手机路由放在 `app/m/`，展示组件放在 `components/mobile/`；金额、状态流转、权限和审计留在共享业务层。
- 列表与搜索保持服务端分页。附件、PDF 和 MRZ 不进入移动首屏必需资源；大文件按需加载，退出预览时释放资源。
- 无权限模块不暴露摘要；直接深链也要由服务端验证。搜索命中与普通概览可走不同路径，但不维护两套命中规则。
- 登录继续使用现有 Cookie 和安全站内返回路径，不增加浏览器持久令牌。公网 PWA 使用有效 HTTPS；局域网 HTTP 可作为普通网页，不能承诺完整安装能力。
- 手机端常规导航和业务操作必须留在 `/m`；完整建单、项目、代理与系统管理不在手机页面放置直达桌面链接。唯一的主动切换入口位于“我的”，并明确标注将进入桌面版。
- 将来如增加 Service Worker，仅缓存明确列出的公开静态资源。订单、搜索、财务、附件和含个人信息的页面不得离线缓存，也不得自动重试写操作。
- 当前 Service Worker 只处理手机导航的通用离线提示以及 `/_next/static/`、图标等公开静态资源；缓存版本独立，未调用 `skipWaiting`，不会在表单填写中强制刷新。
- 验收至少覆盖 360／390／430 像素视口、iPhone 和 Android 真机、慢网、键盘、安全区、长文本、多币种与较大附件。浏览器模拟不能代替真机或目标 NAS 性能测试。
- 开发测试使用隔离环境，不操作现有部署和数据。对外发布前验证构建、ESLint、单元／策略、隔离 PostgreSQL 集成、浏览器、MRZ 传输、备份恢复及 HTTPS 代理，再建立发布版本。

2026-09-24 最终源码已通过 Docker 生产构建／TypeScript、ESLint、54 项单元与策略测试、13 项备份与附件脚本测试、3 项 Docker 准备测试、33 项隔离 PostgreSQL 集成测试及 3 项会话／MFA 安全测试。真实 Chrome 浏览器已覆盖手机深链、订单、搜索、安全页、流程、跟进、收付款、材料上传／预览，以及桌面搜索刷新和订单主流程；360／390／430 像素均无横向溢出且底部导航触控区域不少于 44 像素。Service Worker 已验证只作用于手机范围，缓存不含 API 与业务页面，断网只显示通用提示且不补发写操作。隔离备份完成 25/25 迁移、32 张业务表和附件一致性恢复演练。

同日已部署到 x86_64 目标 NAS：一次性迁移退出码为 0，应用、PostgreSQL、备份与 MRZ 容器健康；订单、附件记录、搜索索引和审计数量与发布前一致。内网与公网 HTTPS 的 manifest 和 Service Worker 均返回 200，`/m` 会保留移动端返回地址进入登录页。NAS 内 20 次登录页请求平均 4.4ms、P95 4.8ms；应用约 97MiB，MRZ 为 CPU 模式、约 693MiB。剩余人工验收是 iPhone／Android 桌面安装、摄像头、文件选择器和脱敏 MRZ 图片／PDF 的准确率与耗时。
