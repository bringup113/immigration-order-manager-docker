# MIGRA 移动工作台交互改进方案

日期：2026-09-24。本文件是对 `v1.0.3` 后续源码的产品与交互评估和实施记录。P0～P2 代码已经完成，通过 360/390/430px 浏览器回归，并部署到目标 NAS；尚未使用真实业务账号完成 iPhone/Android 真机操作，因此键盘、相机、相册与 PWA 手势体验仍须以真机验收补齐。

## 当前实施状态

- 已修正详情模块切换时旧数据短暂出现的问题；同模块刷新继续保留当前界面，避免材料上传后的 MRZ 核对状态因组件卸载而丢失。
- 办理页把当前步骤作为第一张重点卡，完整流程折叠；收支页把未结清计划排在前面，USD 汇总改为可展开信息。
- 工作台日期范围进入 URL，提醒卡显示业务类型和“逾期 N 天/今天到期/N 天后到期”；返回订单后保留原范围。
- 全局搜索空词不再请求业务 API，索引刷新间隔限制为 1、2、4 秒，切换搜索词保留并标明旧结果，返回时恢复关键词和滚动位置。
- 订单日期文案和材料操作触控区域已调整；浏览器回归覆盖移动端提醒、分页、搜索、流程、收付、材料上传、MRZ 与模块切换。
- P1 已完成：提醒分页采用稳定排序；项目/代理命中可查看精确关联订单；材料每行统一为一个上传入口；跟进与收付款使用手机全屏表单并保护未保存内容。
- P2 的代码部分已完成：MRZ 使用手机全屏核对并保护未保存修改；移动订单详情按办理、收支、申请人、合同模块只查询需要的数据；移动工作台跳过桌面月度趋势与余额查询。
- 目标 NAS 已完成部署验收：镜像构建与 TypeScript 检查通过，数据库迁移正常退出，应用、PostgreSQL 与 MRZ 容器健康；内网移动入口、公网登录页和容器最小权限检查通过。部署前备份为 `migra-20260924-061651.dump`。
- 待真机完成的项目包括 iPhone/Android 的 HEIC、软键盘、相机、相册和 PWA 手势验证，以及连接实际规模数据库记录 P95 和响应体大小。

## 结论与边界

四个主入口、与电脑端一致的订单排序、按命中模块跳转、手机内完成流程/跟进/收付/材料操作、权限与版本冲突保护已经具备。当前主要问题不是缺一套新前端，而是**重要内容埋在长列表里，某些手机操作仍像桌面表单，加载状态偶尔会让用户误判**。保留现有 Next.js、API、权限、审计和四个一级入口；订单详情仍为办理与跟进、收支、申请人与材料、合同材料四个模块，不增加独立“概览”。除“我的”主动切换外，常规流程始终留在 `/m`。

工作台提醒继续重要；订单内部的待办和跟进只是辅助信息，不应盖过当前流程、材料与收支。完整建单、模板、计划编辑和管理后台继续留在电脑端。首轮不做推送、离线编辑、原生 App 或 Redis。

## 按手机任务重排页面

| 任务 | 现在的阻力 | 建议的结果 |
| --- | --- | --- |
| 看今天该处理什么 | 工作台按日期列出最多 30 项；数量可能大于可见列表，超出部分没有继续查看入口；提醒卡片主要靠图标区分类别 | 逾期、今天、未来 7 天继续置顶；每条写明“待收/待付/流程/材料/跟进”等类型。每组先显示最急的少量事项，提供按日期继续加载；完成动作返回后刷新该组，而不持续轮询。 |
| 找一张订单 | 列表有搜索、状态、排序与分页，结构正确；卡片的“下一日期”只来自流程和跟进，容易被误解为全订单下一件事 | 保留四项能力及电脑端相同的默认签约日期排序。卡片明确写“当前流程”和“流程/跟进日期”，不要暗示覆盖财务与材料；若以后显示跨模块下一事项，应由服务端批量计算当前页，不对每张订单额外请求。 |
| 看订单正在办什么 | 详情先展示完整流程，当前步骤可能在很多已完成步骤之后；底部业务操作条与主导航同时常驻，占用可视高度 | 顶部压缩为姓名、项目、状态、负责人；当前步骤及到期日作为办理页第一张重点卡。已完成步骤与完整时间线折叠，跟进历史保持次级。四个吸顶模块不变；仅在当前模块和权限允许时显示底部动作，键盘打开时检查安全区。 |
| 看还有多少钱要收付 | 收支页首先显示“预计应收/实际已收/预计应付/实际已付”四个总额，待处理计划要继续往下找 | 第一屏优先显示未结清计划的原币剩余金额、到期日与待收/待付状态；四个 USD 汇总收进可展开区。不能直接用预算汇率下的 USD 计划总额减每笔实际汇率下的 USD 入账总额充当欠款。 |
| 查资料 | 空搜索也会请求最近订单、项目和代理；项目/代理命中只显示摘要，不能继续在手机端查关联订单；结果标题用已加载条数，看起来像总命中数 | 空状态先给搜索提示，不请求业务列表。订单命中继续按 `target_tab` 跳对应模块。项目/代理卡增加“查看相关订单”，由服务端用精确 ID 和现有 `ALL/OWN` 权限筛选到 `/m/orders`；未做精确筛选前，不能用名称模糊搜索冒充关联结果。标明“已显示 N 条”，有更多时显示继续加载。 |
| 补材料、核护照 | 每种材料同时放拍照、选文件、相册三个入口，按钮偏小；材料多时很长；MRZ 字段和护照预览放在长弹窗的不同折叠区 | 每行只放一个 44px 以上的“上传”入口，再选择拍照/相册/文件。默认突出待补材料，已上传材料可展开；保留申请人切换。MRZ 改为手机全屏核对：护照预览可随时查看，校验失败字段突出，最后仍要人工勾选确认。HEIC 先做真机确认，再决定轻量客户端转换或清楚提示格式限制。 |
| 登记收付款 | 现有弹窗一次呈现日期、计划、说明、币种、三种金额/汇率与备注，手机键盘下较长 | 仍分“登记收款”“登记付款”。在 `/m` 内使用全屏表单：先选计划，再填日期和实际原币金额；说明按现有规则带入且可编辑。非 USD 时才展开本位币/汇率计算；保存前显示原币、USD、关联计划和计入金额的确认摘要。**不自动把计划剩余金额写成实际到账金额**，以免误登记。 |

## 先修正的交互状态

1. **切换详情模块时不展示旧模块的材料状态。** `MobileOrderDetail` 切换 `section` 后保留上一份 `data`；办理/收支正文等待新数据，但申请人与材料正文可先用旧响应渲染。旧响应不含文件时会短暂显示“待上传”。记录响应对应的模块，只在匹配时显示材料内容；同模块刷新可保留旧内容并标注更新中。写操作继续禁用至新版本确认。
2. **长表单的取消与返回要有一致行为。** 跟进、收付款与 MRZ 未保存时明确提示，提交中防重复点击；成功后停留在当前订单模块，并把新记录或最新状态放到可见处。不要把表单草稿或业务数据放入 Service Worker 离线缓存。
3. **触控与状态反馈统一。** 材料上传、预览、识别、历史翻页等操作达到至少 44×44px；加载、成功、冲突、网络结果不确定应在操作附近显示。断网或结果不确定时不自动重复收付款/上传。
4. **搜索输入与结果口径清晰。** 保持已有 300ms 输入防抖和仅在 `indexing=true` 时有限递增刷新；修改搜索词或页面隐藏时取消旧请求。输入与当前结果词不同的短暂时段，明确标注结果属于哪个词，不把旧结果呈现为新词结果。
5. **返回时保留上下文。** 目前搜索词和工作台所选日期范围都只在页面状态中，进入订单后点“返回”会重置。工作台范围写入 `/m` 的 URL；搜索关键词和滚动位置在当前浏览器标签内短期保存，返回后重新请求结果，不缓存业务响应，退出登录时清除。订单列表已保存分页路径和滚动位置，沿用这一模式。

## 低配服务器的实现原则

- 先量测，再改查询。手机工作台当前复用 `readDashboard`，同时计算手机首屏没有展示的月度趋势与余额；订单详情按模块已经部分分流，但仍读取多组共用数据。可以在共享查询层增加明确的手机视图/字段投影，**不复制一套移动业务服务**。以 SQL 计数、响应大小和 P95 请求时间比较优化前后。
- 空搜索不发请求；提醒列表超过首屏时使用服务端分页。分页排序必须稳定，包含日期、类型、订单和来源记录 ID，避免重复或漏项。继续沿用现有数据库索引与异步搜索索引；本轮无需加 Redis。
- 材料图片、PDF、MRZ 识别保持按需加载。图片拍摄与上传的压缩/格式处理先在 iPhone 与 Android 真机测耗时、内存和清晰度，不将高成本转换默认放到 NAS。

## 交付顺序与验收

| 阶段 | 改动 | 完成标准 |
| --- | --- | --- |
| P0：正确性和易用性 | **首批已完成**：模块加载状态修正；当前步骤置顶、旧步骤折叠；收支待处理计划置顶；卡片类别和日期文案；返回时保留搜索/日期范围；材料触控区域；空搜索不请求 | 浏览器已验证切页不显示旧材料、返回上下文、360/390/430px 无横向溢出以及权限与订单范围；手机软键盘仍待真机验收。 |
| P1：高频操作 | **已完成**：工作台提醒可继续查看；项目/代理精确关联订单；材料单入口；跟进与收付款全屏表单、未保存确认及完成后的可见反馈 | 浏览器回归已覆盖提醒追加去重、精确 ID 筛选、全屏尺寸、上传来源选择、收付金额/汇率/计划口径，以及冲突和不确定结果不重复提交。 |
| P2：真机和负载 | **代码与 NAS 部署已完成、真机待验收**：MRZ 全屏核对和未保存保护；移动工作台跳过桌面趋势/余额查询；订单详情按模块投影查询。HEIC 继续明确提示转换为 JPEG，不在未测量前引入高成本转换。 | 360/390/430px 隔离浏览器回归覆盖全屏 MRZ；NAS 镜像构建、迁移、健康检查和最小权限检查通过。仍需在 iPhone Safari 与 Android Chrome/PWA 验证安装、键盘、相机、相册、HEIC、文件选择和离线恢复，并记录真实业务路径的响应大小与 P95。 |

上线判断以真实业务路径为准：**提醒 → 对应订单模块 → 处理 → 看见更新结果**；**搜索 → 命中订单或关联订单 → 返回搜索词与滚动位置**；**材料上传 → 预览 → 必要时 MRZ 人工确认**。开发过程继续遵守现有权限、审计、原币金额、计划结清和版本冲突规则。P0/P1 完成后再判断是否需要更大的视觉重设计，避免在流程未顺之前重画整套界面。

## 源码依据

- `app/m/page.tsx`：提醒分类、30 项显示、手动刷新。
- `app/m/orders/page.tsx`：订单搜索、排序、分页及卡片日期口径。
- `app/m/search/page.tsx` 与 `lib/global-search-query.ts`：空词结果、分组、索引同步和加载更多。
- `components/mobile/mobile-order-detail.tsx` 与 `lib/order-detail-query.ts`：四模块、长流程、收支汇总、模块加载状态。
- `components/mobile/mobile-cash-actions.tsx`、`components/mobile/mobile-materials.tsx`、`components/mobile/mobile-workflow-actions.tsx`：手机写操作与表单。
- `tests/mobile-real.browser.cjs`：现有 CI 已覆盖基本路径和尺寸；真机手势、键盘、摄像头与完整视觉层级尚未覆盖。
