# 源码维护审阅

更新日期：2026-09-15。范围为Order4当前源码、构建、测试和维护文档；不读取业务数据库或附件内容。此文档原位更新，不追加逐轮调试记录。

## 判断

业务架构没有失控：数据库层、领域服务、权限、订单范围、审计和文件处理已有独立模块，TypeScript开启strict。主要债务是页面和路由过大、源码排版不统一、历史实现残留、部分测试与文档没有同步。无需推翻系统，但应停止继续向大型组件堆叠功能。

## 本次已整理

- 实施台账从618行精简为当前状态、固定决策、待办和文档导航，删除六份被新实现取代的旧报告/重复记录。历史性能报告与原始统计仍保留。
- 删除旧backup-paired兼容入口，备份统一使用backup-postgres；保留迁移历史、许可文件和所有业务数据。
- Docker只准备PDF浏览器资源，脚本改名copy-pdf-assets；移除identite-ts与Tesseract语言包直接依赖并同步锁文件，清除旧识别链的19个依赖包及约10MB的本地OCR生成资源。
- 展开此前手工压缩的业务页面和状态服务；除登录页内嵌HTML模板外，非UI库TS/TSX源码已无超过500字符的代码行。状态页通过import type复用服务端返回类型，避免重复维护MRZ指标字段。
- 将订单详情的公共展示组件及四个子表拆为独立组件；申请人/材料/MRZ、流程/待办/跟进、计划/实际收付和结案弹窗均已分离。对应动作分别集中到use-order-people-materials、use-order-workflow-actions、use-order-finance-actions和use-order-lifecycle-actions，金额三选二反推仍复用cash-calculation；共享数据、草稿与弹窗类型集中到order-detail-types。订单状态、备注、签订日期、结案及重新开启统一由生命周期控制器处理，并保留后台刷新不覆盖未保存草稿的保护。主组件由约3422行降至880行。
- 展开并格式化订单详情写接口；将30个订单动作的权限、日志名称、日志编码、审计实体及快照目标集中到lib/order-action-policy.ts。新增策略完整性测试，防止后续只加功能却遗漏权限或日志。
- 将订单流程新增/修改、收付款计划新增/排序分别归入order-workflow与order-finance，并把审计快照读取移入order-action-audit；接口仍负责事务和审计，领域规则不再继续堆进路由。
- 新增order-materials与order-applicants领域模块：材料新增/修改/删除、文件目录联动与回滚，以及附属申请人新增/删除和文件隔离已移出路由；共享文件类型判断集中到material-files。
- 申请人资料修改及姓名变更后的附件目录迁移并入order-applicants；MRZ护照文件校验、解析、校验位汇总、人工确认和识别记录写入独立为order-mrz。订单写路由由最初1257行降至564行。
- 通用data接口完成规范排版；11类资源的读写权限、审计实体、摘要和快照表集中到data-resource-policy，并增加资源覆盖测试。新增资源若遗漏权限或日志元数据会导致测试失败。
- 代理、渠道商、币种及项目新增写入下沉到data-resource-mutations；全局搜索、首页统计和新建订单目录查询分别归入global-search-query、dashboard-query与order-catalog-query。通用路由只保留HTTP鉴权、简单列表分发、事务审计和订单负责人校验，由855行降至288行。
- 添加.editorconfig和开发规范；修复依赖旧界面提示文案的静态测试，检查实际文件接收类型及当前构建入口。
- Next.js及其ESLint配置由16.3.4更新到16.3.5，并刷新baseline-browser-mapping、Babel、brace-expansion和js-yaml传递依赖；npm官方公告库对生产依赖及完整依赖树均报告0条已知漏洞。更新后在全新安装环境通过45项测试、TypeScript检查和Docker目标生产构建。
- 修正恢复演练对宿主机Node的隐式依赖：临时库迁移改由一次性postgres_migrate容器执行，附件一致性检查复用主应用容器；Shell命令入口统一记录为可执行文件。v1.0备份已真实恢复到隔离数据库并校验23/23个迁移、32张业务表、5个项目、6个币种、32个流程模板、34个材料模板和18个收付款模板，完成后确认临时数据库已删除。
- 补齐发布门禁：全新 Docker 环境自动创建并清理确定性业务夹具，数据库约束与完整业务测试改为顺序执行，缺少基础数据直接失败而不再静默跳过；备份容器使用准备阶段记录的宿主机 UID/GID，修复 Linux Runner 绑定目录无权写入的问题。
- 清理源码目录内可再生成的.next、.sites-runtime、node_modules残余、TypeScript增量缓存、PDF浏览器构建资源和系统索引文件；目录由约588MB降至约16MB。未触碰.env、data、backups、业务附件或当前容器。
