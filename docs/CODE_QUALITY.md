## 当前结论

当前源码可以继续作为 `v1.0.3` 后续基线：此前的手机工作台、不可达 UI 与重复逻辑清理已经合并；本轮又修复了并发登录限流、MRZ 两位年份、`OWN` 订单审计范围和 MRZ 请求中断清理，并为附件一致性检查增加独立运维权限与协作式分批。页面外观和业务数据没有因此改变。

当前本机 Docker 测试栈已用本轮源码重建，第 26 个迁移已应用，主应用健康。GitHub Actions、浏览器和 NAS 必须以最终提交重新验收；旧提交或旧部署的通过记录不能代表当前源码。

## 代码边界

- 页面和组件负责展示与交互；API 路由负责鉴权、输入、事务入口和响应；业务规则集中在 `lib/` 与领域 Hook。
- PostgreSQL 是唯一数据库。业务写入与审计保持在同一事务，订单级 `ALL` / `OWN` 范围由统一访问条件控制。
- 项目保存可复用模板；订单创建时复制快照，后续模板修改不改变已有订单。
- 申请人创建只要求系统显示名称；护照资料和文件可后补，MRZ 结果必须人工确认。
- 收付款金额使用整数最小货币单位，汇率使用固定精度快照；计划是否结清按计划原币判断。
- 文件和 MRZ 上传采用有界流式处理；临时文件在成功、失败、中断及超时路径中清理。
- 主应用不依赖 MRZ 健康状态启动；识别服务故障只影响识别接口。

## 测试入口

```bash
# ESLint、生产构建及 64 项单元／策略测试
npm test

# 备份、附件一致性和 Docker 环境准备
npm run test:backup
npm run test:prepare

# 以下命令只允许连接隔离应用、隔离数据库和临时账号
npm run test:integration
npm run test:mrz-transfer
npm run test:browser
npm run test:browser:current
npm run test:browser:mobile:real
```

`test:integration` 必须提供 `MIGRA_BASE_URL`、`MIGRA_DATABASE_URL`、`MIGRA_TEST_USERNAME` 和 `MIGRA_TEST_PASSWORD`，缺少时直接失败。MRZ 传输测试还要求 `MIGRA_MRZ_TRANSFER_TEST=1`，并把测试应用的 sidecar 地址指向同一隔离网络中的受控测试容器；不得对正式识别服务执行超限和并发占位测试。
