## 结论

当前代码可以继续作为主线维护，不需要推倒重写。移动工作台 M0～M5 已进入源码，本地生产构建、类型检查、静态检查、隔离接口、真实浏览器、部署权限及成套恢复回归均通过，并已部署到目标 NAS 完成自动化上线验收。

本轮修复 MFA 更换与恢复码并发、跨自定义角色管理、备份锁、失败恢复、附件移动回滚、大额换算、汇率差额提醒、纯 `+` 搜索和结案响应权限边界，并恢复 7 个 Shell 运维脚本的可执行权限。对应回归已进入既有测试入口。

## 当前代码边界

- 页面和组件负责展示与交互；API 路由负责鉴权、输入、事务入口和响应；业务规则集中在 `lib/` 领域模块。
- PostgreSQL 是唯一数据库。业务写入与审计保持在同一事务，订单级 `ALL` / `OWN` 范围由统一访问条件控制。
- 项目保存可复用模板；订单创建时复制快照，后续模板修改不改变历史或办理中的订单。
- 申请人创建只要求系统显示名称；护照资料和文件可后补，MRZ 人工确认仍要求真实文件及完整字段。
- 新订单的模板流程及计划日期由服务端根据签订日期和模板天数计算；手动日期不被后续签订日期修改覆盖。
- 收付款只管理订单计划和实际记录，金额使用整数最小货币单位，汇率使用 `1e8` 精度快照。
- 普通文件和 MRZ 上传均采用有界流式处理；临时文件在成功、失败、中断及超时路径中清理。
- 主应用不依赖 MRZ 健康状态启动；识别服务故障只影响识别接口。
- 运行状态轮询验证会话和权限，但不刷新用户活动时间，避免后台页面无限延长空闲会话。

## 当前测试入口

```bash
# ESLint、生产构建及 54 项单元/策略测试
npm test

# 备份、附件一致性和 Docker 环境准备
npm run test:backup
npm run test:prepare

# 仅允许连接隔离数据库和隔离应用
npm run test:integration

# 需要把测试应用的 MRZ_SIDECAR_URL 指向测试容器
npm run test:mrz-transfer

# 需要 Playwright Chromium、隔离应用和临时测试账号
npm run test:browser
npm run test:browser:current
```

`test:integration` 现在要求 `MIGRA_BASE_URL`、`MIGRA_DATABASE_URL`、`MIGRA_TEST_USERNAME` 和 `MIGRA_TEST_PASSWORD`，缺少时直接失败，不能以跳过代表通过。提醒和排序测试默认复用 `MIGRA_DATABASE_URL`，并只创建连接级临时表。

MRZ 传输测试还要求 `MIGRA_MRZ_TRANSFER_TEST=1`，避免误对普通或生产环境执行并发及超限上传。GitHub Actions 会在隔离 Docker 网络中提供受控 sidecar 响应并执行该测试。
